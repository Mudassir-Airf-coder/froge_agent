# 04 — Hermes Integration

## 1. Connection goal

Hermes connects to the running FROGE MCP endpoint as an MCP client. Authentication uses the runtime token generated by FROGE. The token is a credential and must never be committed, pasted into public documentation, or written to normal logs.

## 2. Startup flow

```text
User: froge-mcp start
        ↓
FROGE starts runtime
        ↓
Endpoint + session ID + runtime token
        ↓
Hermes receives connection configuration
        ↓
Hermes authenticates
        ↓
FROGE returns capability/discovery information
        ↓
Hermes can dispatch to enabled adapters
```

The exact Hermes configuration mechanism remains a separate implementation task because the research archive identifies Hermes as a personal/local project and explicitly marks MCP consumption as `[UNKNOWN]`.

## 3. Hermes skill

The FROGE MCP skill must teach a compatible agent:

- what FROGE MCP is;
- how to connect to its endpoint;
- how runtime authentication works;
- how to discover capabilities;
- how to select an adapter;
- how to submit a task;
- how to read structured status/results/errors;
- how to respect capability risk levels;
- how to avoid exposing the runtime token.

A skill is instructions, not an authentication bypass. Installing/reading the skill does not itself grant access; the MCP connection still requires valid runtime credentials and server-side authorization.

## 4. Verification handshake

The desired terminal/client experience is a clear connection verification step:

```text
FROGE MCP: READY
Endpoint: <local endpoint>
Session: <session-id>
Authentication: VALID
Hermes client: CONNECTED
Capabilities: <count>
```

The final UI wording is implementation detail; the state transitions are the contract.

## 5. Task model

Hermes should submit intent plus explicit parameters. FROGE resolves the requested capability to an adapter and applies policy before execution. Hermes remains responsible for deciding the overall workflow.

## 6. Failure behavior

Hermes must receive explicit machine-readable states for:

- authentication failure;
- adapter missing;
- tool not installed;
- tool unhealthy;
- capability unsupported;
- permission denied;
- task timeout;
- process failure;
- malformed tool output;
- cancellation;
- internal FROGE error.

No failure should be represented as a fabricated success.
